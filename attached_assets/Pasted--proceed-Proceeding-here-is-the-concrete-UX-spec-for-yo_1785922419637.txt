Proceeding: here is the concrete UX spec for your simplified chat + Twin system. The current app already has Chat, Deep Research, Twin, Files, Connectors, Saved Reports, Skills, Community, and Settings in the sidebar, plus AI Partner roles and a skills dropdown in the composer, so the main job now is reducing that complexity into a more legible guest/free-user flow.

Chat model
Chat becomes the primary entry surface for guest and free users, while Deep Research is no longer a separate destination in the user’s mental model and instead behaves as research capability inside Chat. Since the current chat already supports in-thread “Upgrade to Deep Research,” artifact cards, citations, and a composer with selectable options, this is a refinement of the existing structure rather than a complete product rewrite.

Recommended chat modes:

Cofounder

Web Search

Scenario Testing

Composer structure:

Mode dropdown at the left of the input.

Main placeholder: “What are you building?”

Subtext below input: “Describe your idea, product, or company plan.”

Attach, voice, and send remain secondary actions.

Mode behavior
Cofounder is the default mode and should behave like an entrepreneurial thought partner focused on idea shaping, business planning, launch sequencing, product decisions, and actionable next steps. It should be the strongest mode for detecting startup-building intent and for promoting the Twin handoff when the conversation becomes company-oriented.

Web Search should activate outward-looking research behavior: competitors, market facts, trends, customer signals, benchmarks, citations, and evidence-backed answers. This maps cleanly onto the current app’s research-oriented capabilities without requiring “Deep Research” to stay exposed as a separate top-level page for new users.

Scenario Testing should help users explore alternatives and consequences, such as pricing options, launch paths, market risks, target segments, feature prioritization, and “what if” outcomes. This gives you a plain-language UI for the ScenarioLab concept while keeping the user experience simple.

Twin handoff
The current product already positions Twin as a dedicated execution workspace, so the handoff should happen when a chat thread shows clear business-building intent rather than waiting for the user to discover Twin manually from the sidebar. When users talk about building an app, launching software, starting a service, validating a market, generating a business plan, pricing an offer, or setting up founder tasks, the chat UI should surface a contextual Twin prompt.

Trigger examples:

“I want to build an app for dentists.”

“Can this idea become a SaaS company?”

“Generate a business plan.”

“How should I launch this service?”

“What pricing model should I use?”

Recommended prompt copy:

“This looks like a company idea.”

“Start it in Twin.”

“Turn this conversation into a company workspace.”

Twin first screen
Because Twin is still visible in the sidebar, the first click must explain immediate value before showing the full operating dashboard. The current Twin concept on the page is a powerful four-column command center with tasks, documents, publishing, and a narrative rail, but a first-time user needs a simpler entry layer before landing there.

Recommended first-screen copy:

Headline: “Start your company with an AI Cofounder.”

Subtext: “Turn ideas, research, and plans into tasks, documents, and execution.”

Primary CTA: “Start from this idea.”

Secondary CTA: “Import from chat.”

Tertiary CTA: “Open an existing workspace.”

After entry, Twin should auto-create:

Company name placeholder.

One-line company brief from the chat thread.

Starter task list.

Draft business plan or roadmap.

Linked conversation context.

Sidebar structure
The currently visible sidebar includes Deep Research as its own page and keeps capabilities like Skills at top level, which contributes to the feeling of a feature inventory. Your revised structure is better because it centers the product around working surfaces and groups legacy writing utilities under a single Writing Suite.

Recommended sidebar:

UX rules
A guest/free user should feel that the product starts with one question, not with a dashboard. The first interaction should be lightweight and natural, similar to the intent-first onboarding pattern you referenced earlier, while the richer workspace appears only after the user has declared what they want to build.

Key rules:

Default mode is Cofounder.

Keep only three visible chat modes.

Merge Deep Research into Chat behavior.

Keep Twin visible, but make its first screen value-led.

Offer Twin contextually during startup-oriented conversations.

Keep output tools as artifacts, not as primary navigation.

A simple user journey would be: the user opens Chat, stays in Cofounder mode, types “I want to build a clinic scheduling SaaS,” then switches to Web Search for competitors, runs Scenario Testing on pricing or niche focus, and finally sees “Start it in Twin” to turn the thread into a company workspace.
