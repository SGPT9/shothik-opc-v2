# 📄 To-PRD Skill

Use this skill when converting raw features, user requirements, or chat ideas into a production-ready PRD inside `/twin` or `docs/`.

## PRD Structure

1. **Executive Overview & Problem Statement**
2. **User Personas & Key Pain Points**
3. **Functional Specifications & Acceptance Criteria**
4. **Non-Functional Requirements (Performance, Security, A11y)**
5. **Out-of-Scope & Future Iterations**
