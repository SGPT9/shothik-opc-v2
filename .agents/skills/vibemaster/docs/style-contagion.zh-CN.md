# 技能文本就是风格提示词

[English](./style-contagion.md)（权威版本）

一个整天泡在技能文本里的 agent，说话会越来越像那些文本。我们是用真实翻车学到这一课的：一个在本仓库工作的 agent 开始在回复里自造黑话（把英文材料的术语直译铸成外来名词、造出不带解释的压缩标签）直到它的总结需要配解码器才能读。指令从没让它这么干，是它周围的文本教的。

## 机制

语言模型是风格延续器。上下文窗口里装着什么样的散文，输出就以什么为语域范本。技能正文在技能运行时被注入上下文，这意味着**你发布的每个技能同时也是一条隐性的风格提示词**，不管你有没有这个意图。

指令告诉模型做什么，指令周围的散文示范它怎么说话。两者打架时（一条「写得平实」的指令钉在满是自造词的正文上），示范赢过说教，因为正文的体量碾压指令。

## 对技能作者的含义

- **用你希望 agent 说话的语域写正文。** 正文不只是流程，它是模型会模仿的写作样本。
- **正文里的自造词会被 agent 原样复读。** 非造不可的标签，把解释放进同一句话，这样 agent 复读术语时会连解释一起复读，读者才能活下来。
- **描述外来概念，不要直译它。** 从另一种语言或生态铸出的外来名词会被 agent 克隆，但让它可读的语境不会跟着走。用自己的话说清那东西是干什么的。
- **清正文胜过加指令。** agent 满嘴黑话时，解药很少是再加一条规则。去审计它浸泡其中的文本。

## 执行

风格纪律没有棘轮就会退化。我们的棘轮有两层：

- **判断层**：模型对产品文本跑审计：它能发现脚本发现不了的东西，比如没解释的隐喻、泄漏进产品文案的过程痕迹。
- **机械层**：脚本里的禁词表加标点检测，接进 CI。审计每清掉一个词就追加进禁词表，从此它回不来。

同一个形态（纪律写给模型看，闸门拦住手滑）现在守着这个栈的三样东西：表达风格、manifest 一致性、发布步骤的隐私规则。判断层负责发现，脚本层负责守住。

纪律本身的 drop-in 规则见 [rules/plain-language.md](../rules/plain-language.md)。
