# Deliverable Copy Discipline

User-visible deliverables (UI, PDF, slides, reports, screenshots, export files) serve the product or business goal only. They must read like real product content.

- Never write the agent's thinking process, implementation rationale, design reasoning, debugging narrative, or next-step plans into a deliverable.
- No explainer copy in UI. Phrases like "This page demonstrates…", "I will…", "This section shows…" are forbidden unless they are genuine product help text or empty-state copy.
- Implementation notes, verification steps, limitations, and trade-offs belong in chat replies, code comments, PR/MR descriptions, docs, or plan files. Never in the deliverable.
- Exception: the user explicitly asks for design notes, methodology, or process records inside the deliverable.
