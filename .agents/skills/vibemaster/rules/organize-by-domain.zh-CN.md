# 按域组织，不按类型

[English](./organize-by-domain.md)（权威版本）

创建目录、文档、模块时，先按域分组（任务、特性或业务场景），类型文件放在域目录里面。不在顶层建类型桶或分层桶。

- 工作文档：一个任务一个目录（如 `.issues/<YYYY-MM-DD-主题>/` 里放 `spec.md`、`plan.md`、`notes.md`），不建 `plans/`、`design/` 这种把一个任务拆散到多处的类型桶。Kiro（`.kiro/specs/<feature>/`）和 spec-kit（`specs/NNN-feature/`）都是同一个形状。
- 代码：优先按特性分包而不是按层分包（Go 的惯例）。一个特性的 handler、逻辑、类型住在一起，不进全局的 `controllers/`、`services/`、`models/` 桶。
- 判断标准：一个业务单元能不能整体拿走、评审、搬迁或删除？一个任务或特性散落在多个类型文件夹里，结构就是错的。
- 例外：真正跨域共享的资产可以放共享位置，把这个集合保持在很小。
