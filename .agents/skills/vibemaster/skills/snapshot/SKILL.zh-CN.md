# snapshot：任务状态快照

[English](./SKILL.md)（权威版本）

铁律：**读者是一个什么都不知道的新会话。** 合格标准只有一条：只读这份快照就能不重问、不重查、不重新推翻已定决策地继续干。写给自己看的备忘录不合格。

## 写快照（收尾侧）

落盘到工作区草稿目录 `.issues/<YYYY-MM-DD-主题>/snapshot.md`。任务已有目录就写进去。同一任务再次收尾，更新同一份文件（它是活文档，不是日志）。落盘前先确保草稿目录被忽略：`git check-ignore .issues` 不通过时，把 `.issues/` 追加进 `.git/info/exclude`（本地忽略，不动共享 `.gitignore`）并告知用户一句。非 git 环境无提交风险，直接写。

**交接落到哪，决定什么必须跟着走。** `.issues/` 是本机文件（被忽略），未提交变更也只存在于这台机器，读者是本机的下一个会话时这正合适。工作要去另一台机器或别人的 agent 时，本机快照什么都交接不了：把工作推上 WIP 分支，把快照内容装进随仓库走的载体（提交信息、PR 描述，或用户愿意提交的文件），并明说哪些部分留在了本机。

五节结构，按新会话的需要排序，不按时间顺序：

1. **目标与现状**：一句话说清任务是什么、整体走到哪一步。
2. **已定决策（不要重开的问题）**：每条带依据。新会话最大的浪费是重新推翻拍过板的事：依据写足，这一节绝不概括。
3. **已验证状态**：改了哪些文件、测试与 lint 的实际结果（过没过、用什么命令跑的）。没验证的写「未验证」，不许写「应该没问题」。
4. **下一步与卡点**：按序待办，每条带足上下文。卡点单列，等用户拍板的问题原样保留，不替用户做决定。
5. **现场指针**：分支、未提交变更、要重跑的命令、关键文件路径、回滚点，以及继续干活需要跑着的东西（dev server、容器、必需的环境变量）。

内容纪律：

- 写状态不写剧情。压缩标准是「新会话需要什么」，不是「这次会话发生了什么」。
- 一屏是预算。超过约 40 行，多半在写剧情，或在复制一个指针就能指到的内容。
- 风险分两类：**接受了的代价**（标明不要重开）和**待解决的问题**（进卡点），不混写。
- 专项流程已有落盘文件时（诊断记录、spec、发散产出），不复制内容，只写指针加一句当前状态。

## 恢复（开工侧）

1. **找到快照**：用户指定的那份。否则扫 `.issues/` 各任务目录：只有一份明显的近期候选就用它，几份都可能时一行一份列出来让用户认领。最新只是平手时的裁决，不是判据。
2. **信决策，验事实。** 已定决策直接继承，不重新讨论。现实快速核对（分支、`git status`、快照指到的文件和测试结果）：现实可能已漂移，以现实为准，漂移写回快照。
3. **先报告再开工。** 「上次做到哪了」是个问题，先回答它：目标与进度、验证态、下一步、卡点，几行说清，漂移一并说。用户点头再动手。只有请求本身就说了继续，才不停顿直接干，卡点仍然先亮出来。
4. **把活分流到该去的地方**：接着写码走 coding 的循环，原因未知的异常去 dig，需求原来没定的回 shaping。

## 与平台的分工

压缩当前会话归 harness 的 /compact，项目长期经验归平台记忆，原样回放会话归 resume。本技能只做这三样都不做的事：**人为定义结构、给任意下游（新会话、另一个工具、另一个人的 agent）读的精炼任务快照**。对外发布（Issue/PR）不直接贴快照原文，先蒸馏成公开可读的定稿。

## 静默退出

这个技能不适合的请求（测试快照、虚拟机镜像、压缩当前对话）直接完成。零仪式，不提本技能。判断不了适不适用，就当不适用。

## 红旗：出现这些念头就停

| 念头 | 现实 |
|---|---|
| 「把聊天记录概括一遍就是快照」 | 读者要的是状态不是剧情，剧情压缩完还是剧情 |
| 「决策写结论就行，不用写为什么」 | 没带依据的决策必被新会话重新推翻，白拍一次板 |
| 「测试应该都过了」 | 验证态只认实跑结果，没跑过就写没跑过 |
| 「下一步让接手的自己想」 | 收尾这一刻你是最懂现场的人，这份认知不落盘就没了 |
| 「快照落盘了，交接就完成了」 | 被忽略的文件和未提交变更不会跟着工作去另一台机器或别人的 agent。见交接落点段 |
| 「恢复就是马上开干」 | 用户问的是现状。先报告，点头再继续 |
