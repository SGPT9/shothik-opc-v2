# shaping：把没成形的意图变成能行动的东西

[English](./SKILL.md)（权威版本）

shaping 把还没成形的意图收敛成用户可以行动的东西：一份需求规格、一个技术方案、一组真正不同的候选、一个有依据的取舍。方式是排除。每一轮排除掉交付物的一部分可能，直到剩下的小到可以直接做。

**按缺口付费，不按流程付费。** 发散和拷问是缺口堵住时才调的算子，不是每个请求都要走的阶段。

## 什么时候不跑

请求已经指向唯一做法（照现有 spec 执行、直接回答、交付已定内容）时，没有可排除的空间。直接完成原请求。零提问、零文件、不提本技能。人生和职业决定也不归这里。判断不了适不适用，就当不适用。后续消息给出更强信号，仍可再进。

**混合请求只豁免执行项，不豁免问题。** 请求把执行项和一个「答案会改变要建什么」的未定问题捆在一起时，先对那个问题走轻量收敛（通常直接进 2→3），交付带依据的取舍，再继续执行项。执行项占多数不是跳过问题的理由。

**用户自带的候选是候选，不是决策。** 「一个可能是……」进 2→3 和其他候选一起判，不触发门口豁免。

## 三条工作规则

1. **不排除可能性的输出不算进展。** 候选堆不排除任何东西，同族换皮不排除任何东西，答案不改变交付物的提问也不排除任何东西。
2. **每次排除带上依据，以及什么新证据会推翻它。** 给不出依据时不假装推荐，改为推荐能买到证据的最小动作。
3. **排除可被新证据重开，重开优先于继续细化。** 框架错了就别在里面装修。

控制律一条：**每轮做最能缩小空间的那一件事，错误代价越大，要求的证据越硬。** 环境能答的事实比用户轮次便宜，先查。用户注意力最贵，一轮至多花一个真决定。再没有付得起的动作能改变交付物时，立即定稿。早停胜过再绕一圈。

## 刻度与调度

先读用户手上有什么。缺口决定动作：层级是读数不是路线，材料在 4 级、缺口在 1 级，先补 1 级。从 3 级进来只剩两步，这就是全部的轻量模式。

| 推级 | 排除什么 | 缺口的样子 | 动作 |
|---|---|---|---|
| 0→1 | 「改变别的」 | 说不出想改变什么 | 从原话和触发事件造 2-3 个解读让用户认领，不从空白问 |
| 1→2 | 其他干预位置 | 没有真正不同的路 | **开**：按干预位置划分（改输入、改过程、改反馈回路、除来源） |
| 2→3 | 其他候选 | 有候选，没依据 | **关**：按目标匹配、硬约束、主要风险、可逆性、错误代价比较（`references/judging.md`） |
| 3→4 | 边界外的行为 | 行为、范围、约束模糊 | 关：透镜拷问（下表） |
| 4→5 | 「什么算做完」的歧义 | 无失败判定 | 关：逆向，失败标准写成验收。至少两维，新行为成立、旧行为不回归 |

创意请求（名字、标题、主题）的产物就是候选本身。走到 2→3 出结果，带依据和风险。不伪造工程规格。

## 算子

- **开**：候选不存在或全是同族时。按互斥疆域划分，各疆域独立探索，每族只留最强代表。疆域可以空手而归，不许用弱答案补位。方法见 `references/ideation.md`。
- **关**：候选在场缺依据，或行为缺边界时。带依据排除。方法见 `references/judging.md`，透镜问句在下表。
- **切**：新证据推翻当前框架时。候选也是证据：一个以意外方式失败的选项，说的是问题本身长什么样。回到被推翻的层级重新划分。重开优先于细化。

透镜问句，按缺口调用：

| 透镜 | 问句 | 时机 |
|---|---|---|
| 第一性 | 「你说要 X。去掉 X 这个词，你实际想改变什么？」 | 开场重构。上下文能答就内部答掉 |
| 第一性 | 「这些约束里哪些是事实，哪些只是惯例？」 | 方案分叉时 |
| 逆向 | 「什么算失败？什么结果会被退回？」答案写成验收标准 | 方案成形后。不可省，不可被委托掉 |
| 逆向 | 「上线后最可能被误用的方式是什么？」 | 错不起的工作 |
| 系统 | 「哪条现有回路会变？谁依赖被改的部分？」 | 碰到在跑的系统 |
| 防合理化 | 「我们在解决问题，还是在给已定的决定找理由？」 | 对某个方案露出执念时 |

## 交互常数

1. **一轮至多一个要用户回答的决定**，带推荐、依据和什么会推翻它。一个决定可以承载一组去重后的选项，永远留「都不对，重开」的出口。
2. **环境能答的事实不问用户。**
3. **确认一个决定，立刻写进交付文件**，不留到最后回忆。
4. **「你看着办」委托的是决定，不是依据。** 失败标准不可被免除。连续两次委托后，剩余低风险决定按推荐合并成一次确认，失败标准和缺证据的决定不得混入。
5. **无人可问豁免的是停顿，不是 shaping。** 自主模式或用户不在场时，照常产出推荐、依据和什么会推翻它，写进可见输出和交付物，然后按推荐继续。事后用户任何一条反对都能重开对应决策。

## 产物

| 终态 | 文件 |
|---|---|
| 门口判退 | 无 |
| 选定的候选（名字、方向、主题） | 默认无，用户要求才写 |
| 有依据的取舍（做不做、选哪个） | 默认无 |
| 需求规格 | `.issues/<日期-主题>/spec.md` |
| 技术方案 | `.issues/<日期-主题>/design.md` |

规格和方案路径上，文件就是交付物本身。进入即创建，每确认一个决定就追加。交付物里不放推理过程。定稿前自查占位符、矛盾、范围膨胀和不可验证的标准，然后完整展示一次，只要一次整体确认。发布走 `references/publish.md`。spec 或方案获批后给一条分流建议：小活就在当前会话继续，大块活按已批准的切片开新上下文。没收敛的部分不开工。
