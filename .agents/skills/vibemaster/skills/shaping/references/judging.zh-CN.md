# 判断：带依据地排除

[English](./judging.md)（权威版本）

关算子触发时读这份：候选要选了、一个推荐即将带上实质下行、或某个选择背后的证据有争议。

## 先把输入分拣

比较任何东西之前，先分开四种：

| 种类 | 检验 |
|---|---|
| 已核实事实 | 环境、记录或直接观察撑得住吗？ |
| 二手转述 | 谁说的，他实际能观察到什么？ |
| 推断 | 在解读哪个事实，还有什么别的解读也说得通？ |
| 价值 | 用户在乎什么、能忍什么、欠着什么？ |

不许因为一个推断听起来精确就把它抬成事实。不许把价值当成查资料能定的事实。先用这四种把局面说回去，再要更多。

缺信息改变的是判断的确信度，不是给不给。先给带条件的版本，点名缺的那块。几种解读都活着时，逐个说清什么证据能区分它。一个问题能干净切开时，优先用二元反事实，并说明每个答案把下一步带向哪里。切不开就给一小组可认领的选项，带「都不对」的出口，不许开放式回忆。

## 找到真正的决定

要不要，先于怎么做。做得再漂亮也回答不了这件事该不该存在。产品或功能，查四样：

- 需求：真实反复出现的场景，不是「觉得该有」
- 供给：手上现成的东西是否已经覆盖
- 机制：这个动作实际改变什么
- 证明：什么结果算改善

判断压在只有用户能提供的容忍度或价值上时，具体点名它。「只有你能决定」只在说清了「只有他知道什么」时才有用。

## 用同一套单位比较

1. 与真实目标的匹配。
2. 硬约束。
3. 主要下行，以及谁承担。
4. 可逆性。
5. 错误的代价。
6. 什么证据能早点暴露错误。

先给每个活着的选项摆最强理由，再倾向。过不了硬约束的选项不配等量笔墨。没有方向时给两三个机制不同的起点。有方向时就检验它，不许拿自己的口味换掉。

## 交付

依据够：倾向、它靠什么成立、最可能推翻它的条件、什么时候该改选最强替代、适合行动时的第一个可逆动作。

依据不够：已经能下的结论、还不知道的、最能挪动决定的那一件证据、拿到它的最小办法。

无论哪种，用户带着内容离开，不是只带着一个问题或一段「该怎么想」。

## 深度

短请求一遍过：读到的局面、倾向、什么会改变它。只有难以回头、下行实质、或第一遍之后仍不确定时才加深。长线设计再加：能早暴露错误的反馈、能复利的部分、下行的上限、停下的条件。

## 边界

- 不许替用户编数字、时间线、处境或容忍度。
- 他不确定了多久、多强烈，说明这事要紧，不说明它因何而起。
- 不拿偏差名当诊断。用平常话问反问句：不说「这是沉没成本」，说「从今天起算，接下来一个月的投入还值不值？」
- 已定的纯交付请求交出去，不翻回来重审。
