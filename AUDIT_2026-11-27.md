# Security & Code Audit — shothik-opc-v2

Audit date: 2026-11-27. Base commit: `41da484` (main).

## Act now (outside the code)

These secrets were committed to a **public** GitHub repo. Removing them from the code does not make them safe again, because they stay in git history and anyone may already have copied them. **Rotate every one of them.**

## Findings & fixes in this patch

### Critical

1. **Hardcoded production credentials** (see table above). **Fixed:** every script now reads `INSFORGE_DATABASE_URL`, `INSFORGE_API_KEY`, `INSFORGE_ANON_KEY` and `INSFORGE_BASE_URL` from the environment, and stops if they are missing.
2. **Unauthenticated superuser DDL endpoints.** `app/api/admin/remediate-insforge` and `app/api/tools/remediate-insforge` were public `GET` routes. They connected as the Postgres superuser and ran `ALTER TABLE … OWNER`, changed RLS policies and created extensions. **Fixed:** both routes are deleted. The same SQL still exists in `fix_insforge_rls.mjs` for manual runs.
3. **Convex JWT private key in source.** This key let anyone forge user tokens. **Fixed:** the key is now read only from `JWT_PRIVATE_KEY`. The JWKS public modulus comes from `CONVEX_JWT_PUBLIC_KEY_N` or is derived from the private key. The silent "fall back to the committed key" paths in `user-token.ts` and `auth-diagnostics.ts` are removed.
4. **Forgeable API auth tokens in production.** `api-server/src/routes/auth.ts` used Supabase's publicly known local demo secret (`super-secret-jwt-token-with-at-least-32-characters-long`) whenever `SUPABASE_JWT_SECRET` was unset. That meant anyone could mint an HS256 token the server would accept. **Fixed:** production never accepts the demo secret. Production startup also now fails if `JWT_SECRET` is shorter than 32 characters.
5. **Remote code execution through `/api/v1/sandbox/run`.** The route runs user-supplied bash, python or node code directly on the API host. The only guard is a regex blocklist that is easy to get around (for example `cat /proc/self/environ`, `curl`, or base64 tricks). Outside production it didn't even require login. **Fixed:** in production the route is now off unless `CODE_SANDBOX_ENABLED=true`, and a valid login is always required (except inside the test runner). Only turn it on for a separate, isolated runner, such as a container with no network or secrets.

### High

6. **Every `pnpm` script failed.** `pnpm-workspace.yaml` had `msgpackr-extract: set this to true or false`, which is placeholder text left in place of a real value. pnpm 11 rejects it, so `typecheck`, `test` and `build` all failed before starting. This is the most likely reason CI on `main` was red. **Fixed:** set to `false`.
7. **Typecheck could not pass.** The API server imports `lib/db` and `lib/api-zod`, which must be compiled first (`tsc --build`), and no script did that. This caused 30+ `TS6305` errors. **Fixed:** added a `typecheck:libs` script and made `typecheck`, `typecheck:api` and `typecheck:all` run it first.
8. **Frontend crash bugs and 37 type errors in `artifacts/shothik`.** **Fixed:**
   - `twin/page.tsx` used Next.js `dynamic()` without importing it, in a Vite app. That throws a `ReferenceError` and the Twin page fails to load. Changed it to `React.lazy`.
   - `ArtifactPanel.tsx` pop-out button used an undefined `title` variable, which throws when clicked. It now uses `docTitle`, `sheetTitle` or `slidesTopic`.
   - `CanvasSkeletonPreview` was missing its required `tab` prop.
   - `Transcript.tsx` passed an invalid persona `"core"`.
   - `FleetAgent` was missing the optional `model` field.
   - The lazy-loaded components in `ArtifactPanel` and `Composer` were typed wrong, which caused 20+ false prop errors.
   - Supabase table typings for `key_custody` were missing.
   - Result: **0 frontend type errors** (down from 37).
9. **The pre-commit secret scanner missed all of these leaks.** It skipped `.mjs` files, checked only `api-server/src` and `packages/gortex`, and had no rules for DB URLs or PEM keys. **Fixed:**
   - It now scans the frontend, `lib`, `app`, `scripts`, `supabase`, root files and `.cursor/mcp.json`.
   - It now covers `.mjs`, `.cjs` and `.toml` files.
   - New rules detect inline PEM private keys, DB URLs with real passwords, and InsForge and Context7 keys. I checked that they catch the original leaks.
   - Files that hold only made-up sample data can opt out with `// secret-scan: demo-values-only`.

### Medium

10. **Rate limiting saw the proxy's IP instead of the user's.** Express did not have `trust proxy` set, so behind Vercel, Nginx or Cloudflare all clients shared one IP and one 100-requests-per-minute bucket. **Fixed:** `app.set("trust proxy", TRUST_PROXY_HOPS ?? 1)`.
11. **Internal error details leaked to users.** The central error handler returned raw `err.message`, including SQL text, on 500 errors. **Fixed:** production now returns a generic message for 5xx errors.
12. **Committed build and test artifacts.** `cloudflare-worker/node_modules` (TypeScript binaries), `playwright-report/` and `test-results/` were tracked in git (210 files). **Fixed:** removed from the index and added to `.gitignore` (along with `.claude-flow/logs/` and `*.pem`).

### Not fixed — needs your decision

- **Most API routes don't require login.** Out of 168 route files, none use `requireAuth`. Routes call `resolveUserId(req, "usr_default")` instead. In production this means everyone who isn't logged in reads and writes the same shared `usr_default` or `guest` data (files, connectors, projects). This looks like an intentional "guest mode", but it is a real data-isolation risk. I'd suggest adding `requireAuth` to everything under `/api/v1` except a short public allowlist. I didn't make this change because it alters product behavior and could break the frontend's guest flows.
- **Root `app/` folder looks unused.** It is a Next.js `app/` tree, but the deployed build (`vercel.json`) is the Vite app in `artifacts/shothik`, and there is no root `next.config`. Consider deleting it, or `artifacts/shothik/src/app-next`, to reduce attack surface and confusion.
- **Repo clutter.** Root-level one-off scripts (`check_*.mjs`, `verify_*.mjs`), `document.pdf`, `output.md`, `scratch/`, `screenshots/`, and many `*_AUDIT.md` files make the repo hard to navigate. Consider moving the scripts to `scripts/ops/`.
- **42 open PRs and 69 branches.** Many are probably stale and should be triaged.

The 16 API test failures are integration tests that need live Postgres (5432), Redis (6379) and the Python voice server. They fail the same way before and after this patch, and should pass in an environment where those services are running (e.g. `docker-compose up`).
